# POS regression coverage

This matrix describes checks on the main POS branch. Backend HTTP tests in this suite use isolated database doubles. A passing rollback assertion proves the handler requested rollback. MySQL locks, constraints and persisted balances still require a disposable database drill.

| Shop workflow | Automated evidence | Remaining acceptance check |
|---|---|---|
| Bill and collect payment | Billing HTTP and money/payment tests exercise saved checkout IDs, changed prices, invalid quantities, cash change and database errors. Frontend tests exercise retry and product lookup. | Concurrent counters selling the last batch, real on-disk commit and lost response, receipt and scanner hardware. |
| Sales returns | POS operations HTTP test rejects returning more than the remaining sold quantity and returning a free bonus item. Both roll back before stock changes. A successful partial return checks the requested stock increments across two original batches, GST totals, refund and commit. | Successful partial/full return with persisted batch stock, refund ledger and reports; invoice void after a partial return. |
| Purchases and supplier dues | POS operations HTTP test covers settlement, overpayment and rollback after a simulated balance write failure. Frontend inward tests cover selected import formats. | Purchase posting, edits and deletes with existing payments; batch creation and stock conservation through a real sale and return. |
| Local backup and restore | Restore HTTP test checks missing login, blocked counter role, confirmation and exactly one invocation of the restore service. | Restore an actual shop dump to a separate MySQL instance, verify row counts and login, run a bill, verify Drive scheduling and credentials. |
| Cash and books | Ledger tests cover manual-entry edits/deletes, protected rows, named ledgers, scope and display labels. Closing UI tests check required rows. | Counter handover through day closing and financial totals against posted transactions. |
| Product maintenance and reporting | Tests cover selected wholesale default behavior, barcode lookup and report navigation/approval. | Mass price changes, partial import recovery, report totals against real invoices and physical label output. |
| Access controls | Protected routes exercise selected permission denials and accepted roles, including restore. Counter login tests exercise password hashes, inactive accounts, selected counter claims, matching login/logout events, and login after a session-history outage. | Password changes and session expiry, all role-to-tab and API combinations. |
| Gate passes | A security login creates an outbound pass, verifies its number and loading times, and a counter login is refused. | Concurrent pass allocation, inbound unloading and printing. |
| Staff payroll | Monthly rollup combines daily pay, half-day attendance, overtime, bonus and advance and distinguishes paid from pending salary. | Posting salary, adjustments and cash ledger reconciliation in MySQL. |
| Quotations | A cashier needs approval; the approved quote uses line quantities and GST for persisted amounts and advances the daily sequence. | Concurrent numbering, print and saved-quote retrieval. |
| Special orders | Final payment clears the balance and a repeated payment is rejected. | Creating and amending orders and reconciling receivable reports. |
| Customers, users and vouchers | Customer mobile normalization, contact edits preserving loyalty, invoice lookup, creditor payment, expense posting and cashier password protection. | Loyalty redemption and reconciliation against posted financial reports. The optional real MySQL voucher drill verifies simultaneous expense and creditor vouchers, creation of one shared supplier, and rollback after a forced supplier failure. |
| Printing | Server queue classification, desktop queue selection, concurrent receipt and barcode jobs, and failed spool submission. | Print one receipt and scan one printed label on each physical printer and driver combination. |

Install dependencies with `npm ci` in both backend and frontend. From the repository root run `npm run test:changed` for working-copy edits, including staged and new files. Use `npm run test:changed -- --base <full-commit-sha>` to compare committed versions. Append `--list` to preview selected files. Run `npm run test:all` for a release check.

The selector maps changed filenames to overlapping shop workflows. Shared or unrecognized runtime changes run the full suite. When adding a feature, update the mapping alongside its tests. The GitHub Actions workflow checks changes on pull requests targeting main and pushes to main. Scheduled and manual runs execute the full suite. The daily schedule is 2:17 a.m. India time. Results appear under Actions → POS regression when the workflow is on GitHub and Actions is enabled.

For the MySQL voucher drill, set BADIZO_TEST_VOUCHER_MYSQL=1 and supply DB_USER and DB_PASSWORD for a development MySQL account on localhost with permission to create and drop databases. Run `node --test backend/tests/voucherMysql.test.js`. The test creates a randomly named empty QA database and removes it on completion.
